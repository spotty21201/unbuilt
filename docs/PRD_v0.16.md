# Unbuilt — Feature 11: Real AI assistant

Authorized 30 October 2026. The owner's Feature 11 numbering supersedes historical roadmap numbering. This extends Features 9–10 and the interpretation/measurement contract in v0.35. Preserve all earlier requirements and tester prompts.

The assistant translates an intention into a hypothetical whole-plan experiment, a clarifying question, selected measured findings, or an explicit capability/evidence limit. The language model never supplies authoritative quantities or changes accepted work.

- Open the planning assistant and enter an Intention for AI. The selected object is visible context; experiments affect the whole accepted plan. Only supported input values and engine facts go to the active connection. Source notes, media, saved schemes and original source geometry are excluded from the model payload.
- Supported proposals patch generated circulation, frontage (6–30 m), lot depth (12–40 m), or eight project cost assumptions. Review exact changes and held inputs first. Manual lots, reshapes and assigned homes hold regeneration; manually routed streets hold circulation family. Prices, owner benchmark, target, boundaries, entrance, green commitments and individual homes cannot be changed by an AI tool.
- Run reviewed experiment measures the unapplied proposal with the same engine used by manual feasibility. It reports quantities, finance and sequential land-allowance attribution. Explain measured result asks AI to select relevant findings from those results. All displayed measured statements are composed by the engine; unchecked numeric prose and causal assertions never become evidence.
- Review on plan opens the existing accepted-versus-trial drawings and full cost review. Apply alone changes accepted inputs, as one Undo/Redo step. Manual refinement in this review is allowed and its final inputs are recorded. Discard, Cancel, Escape or failures retain accepted work. Applied inputs can be saved as a named alternative through Feature 10.
- Requests, proposals and results bind to the exact accepted snapshot, including selection and numerical precision. Changed inputs, selection changes, cancelled requests and superseded responses cannot revive an old answer. Recheck validity and the binding before review and Apply. No autonomous tool loops or automatic application.
- Four model tools only: propose experiment, select measured facts, clarify, explain a known limit. Strict independent argument validation rejects unsupported fields, invented tools, multiple calls, non-finite or out-of-range inputs, and held-work conflicts. Local measured tools and the fixed-rule search remain usable without AI and are labeled separately.

The owner also requested an administration layer for changeable routing and API keys. AI settings provides primary/alternate completion connections with editable names, endpoints, model identifiers and replaceable/removable keys. Switching is explicit. There is no automatic alternate-provider retry. Administrator authorization is required for reading/editing settings and testing connections. Stored keys never return in responses or enter project persistence/export. Blank key fields retain stored keys; explicit removal clears them. Changes carry a configuration revision, rejecting concurrent overwrites and obsolete in-flight replies.

The server stores private routing configuration outside the repository, using an atomically replaced file with owner-only permissions. A single server process owns this configuration. See AI-ADMIN.md for deployment and access-token setup. A configured key is not proof of a working model: status distinguishes unconfigured, untested, verified tool response and failure. Verification is reset on changes and restart. The connection test makes a small real tool call when actual credentials are supplied.

Calls have a 20-second upstream deadline, a 25-second client deadline, one model call per action, at most two simultaneous upstream calls, bounded request/output sizes, cancellation propagation and no hidden retries. Model responses and remote error bodies never become project data. This increment uses the existing completion protocol and standard HTTP facilities without an additional SDK dependency.

Verification uses an explicitly labeled scripted protocol fixture until the owner supplies routing points and secrets. It proves integration and rejection paths, not real model access, response quality, entitlement, suitability or planner acceptance. No real-model round trip is claimed at this handoff. Features 8–10 tester prompts remain unchanged; independent planner testing remains deferred.
